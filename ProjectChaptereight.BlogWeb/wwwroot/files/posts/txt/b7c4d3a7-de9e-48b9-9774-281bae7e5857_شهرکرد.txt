در الاستیک‌سرچ امکان **تغییر مستقیم مپینگ یک فیلد موجود** یا تغییر نوع داده‌ی آن بدون ساخت ایندکس جدید وجود ندارد. اما برای اینکه نام ایندکس نهایی دقیقاً همان `monitoring_log` باقی بماند، می‌توانید از **روش Reindex و به‌کارگیری Alias (نام مستعار)** یا **روش Reindex با حذف و بازسازی ایندکس اصلی** استفاده کنید.

---

### روش اول: استفاده از Alias (روش حرفه‌ای و بدون Down time)

در محیط‌های عملیاتی بهترین کار استفاده از Alias است تا کدهای برنامه‌تان تغییر نکند.

۱. **ایجاد ایندکس جدید با مپینگ صحیح (مثلاً `monitoring_log_v2`):**

```json
PUT /monitoring_log_v2
{
  "mappings": {
    "clsformactionentry": {
      "properties": {
        "action": {
          "properties": {
            "formChangeSet": {
              "type": "nested",
              "properties": {
                "fieldCaption": {
                  "type": "text",
                  "fields": {
                    "keyword": {
                      "type": "keyword"
                    }
                  }
                }
              }
            }
          }
        }
      }
    }
  }
}

```

۲. **انتقال داده‌ها از ایندکس قدیم به جدید:**

```json
POST _reindex
{
  "source": {
    "index": "monitoring_log"
  },
  "dest": {
    "index": "monitoring_log_v2"
  }
}

```

۳. **حذف ایندکس قدیمی:**

```json
DELETE /monitoring_log

```

۴. **ایجاد Alias با نام exact `monitoring_log` روی ایندکس جدید:**

```json
POST /_aliases
{
  "actions": [
    {
      "add": {
        "index": "monitoring_log_v2",
        "alias": "monitoring_log"
      }
    }
  ]
}

```

> **مزیت:** از این به بعد تمام کوئری‌ها و درج داده‌ها روی `monitoring_log` بدون هیچ مشکلی مانند قبل کار خواهند کرد و ایندکس واقعی زیرین `monitoring_log_v2` خواهد بود.

---

### روش دوم: Reindex موقت و بازگرداندن به نام اصلی `monitoring_log`

اگر اصرار دارید که نام خود ایندکس (و نه Alias) حتماً `monitoring_log` باشد، مراحل زیر را دنبال کنید:

۱. **انتقال داده‌ها به یک ایندکس موقت (`monitoring_log_temp`):**

```json
POST _reindex
{
  "source": {
    "index": "monitoring_log"
  },
  "dest": {
    "index": "monitoring_log_temp"
  }
}

```

۲. **حذف ایندکس اصلی قدیمی:**

```json
DELETE /monitoring_log

```

۳. **ساخت مجدد ایندکس اصلی `monitoring_log` با مپینگ درست:**

```json
PUT /monitoring_log
{
  "mappings": {
    "clsformactionentry": {
      "properties": {
        "action": {
          "properties": {
            "formChangeSet": {
              "type": "nested",
              "properties": {
                "fieldCaption": {
                  "type": "text",
                  "fields": {
                    "keyword": {
                      "type": "keyword"
                    }
                  }
                }
              }
            }
          }
        }
      }
    }
  }
}

```

۴. **انتقال داده‌ها از ایندکس موقت به ایندکس اصلی:**

```json
POST _reindex
{
  "source": {
    "index": "monitoring_log_temp"
  },
  "dest": {
    "index": "monitoring_log"
  }
}

```

۵. **حذف ایندکس موقت:**

```json
DELETE /monitoring_log_temp

```

---

### نکته بسیار مهم پیش از انجام عملیات:

* اگر سیستم شما در حال **درج داده‌های جدید (Write/Index)** روی `monitoring_log` است، حتماً درج داده را در طول فرایند Reindex متوقف کنید یا از **Index Template** استفاده کنید تا داده‌های جدید با مپینگ جدید ذخیره شوند.
